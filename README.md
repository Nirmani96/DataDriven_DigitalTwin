# ED Digital Twin (10-Minute Resolution)

A database-driven discrete-event digital twin of an Emergency Department (ED),
forecasting patient arrivals and discharges over a **12-hour horizon** at
**10-minute resolution** using stochastic simulation with 100 replications.

## Overview

This digital twin models patient flow through an Emergency Department. It uses
historical visit data to fit statistical distributions for arrivals and
length-of-stay (LOS), then runs stochastic forward simulations from a chosen
forecast point.

The model produces:
- 10-minute resolution forecasts of arrivals and discharges
- 95% confidence intervals across 100 replications
- Validation metrics (MAE, RMSE, MAPE, sMAPE, DTW similarity)
- Plots comparing simulated vs actual patient flow

## Data

This model was developed and validated using Emergency Department data from
Rambam Hospital, Israel, as published in:

> Armony, M., Israelit, S., Mandelbaum, A., Marmor, Y. N., Tseytlin, Y., &
> Yom-Tov, G. B. (2015). On patient flow in hospitals: A data-based
> queueing-science perspective. *Stochastic Systems*, 5(1), 146–194.
> DOI: [10.1214/14-SSY153](https://doi.org/10.1214/14-SSY153)

The raw `.mdb` database files are **not included** in this repository.
To reproduce results, obtain the dataset from the authors of the above paper
and place the `.mdb` files in the following structure:

```
data/input/<subfolder>/<filename>.mdb
```

Each `.mdb` file must contain a `visits` table with at minimum:

| Column       | Description                        |
|--------------|------------------------------------|
| `entry_date` | Patient arrival datetime           |
| `exit_date`  | Patient departure datetime         |
| `entry_group`| Patient group flag (filter = 1)    |
| `exit_group` | Exit group flag (filter = 1)       |

## Installation

### Requirements
- Windows OS (required for Microsoft Access ODBC driver used by `pyodbc`)
- [Anaconda](https://www.anaconda.com/) or Miniconda

### Steps

```bash
# 1. Clone the repository
git clone https://github.com/<your-username>/<your-repo-name>.git
cd <your-repo-name>

# 2. Create and activate the conda environment
conda env create -f environment.yml
conda activate ed-digital-twin

# 3. Install the Microsoft Access ODBC driver if not already installed
#    Download from: https://www.microsoft.com/en-us/download/details.aspx?id=54920
```

## How To Run

### Step 1 — Set your forecast date

Open `config.py` and set `FORECAST_DATE` to the datetime you want to forecast from:

```python
from datetime import datetime
FORECAST_DATE = datetime(2007, 9, 20, 12, 0)  # year, month, day, hour, minute
```

### Step 2 — Generate LOS parameters

Run `LOS.py` to fit Gaussian Mixture Models to the last 2 weeks of
length-of-stay data. This creates a JSON parameter file used by the simulation:

```bash
python LOS.py
```

Output: `data/input/parameters/los_parameters_weekday_<YYYY-MM>.json`

### Step 3 — Run the digital twin

```bash
python Digital_Twin_10_minute.py
```

## Outputs

All outputs are saved automatically based on your forecast date:

| Location | Contents |
|---|---|
| `data/output/<forecast_datetime>/` | Validation CSVs (per-replication and aggregate) |
| `data/plots_12h/<forecast_datetime>/` | Forecast vs actual plots |

Key output files:

- `dt_fixed_validation_per_replication_10min.csv` — metrics per simulation run
- `validation_12h.csv` — aggregate validation metrics
- `dt_actual_vs_simulated_arrivals_10min.csv` — arrivals comparison
- `dt_actual_vs_simulated_discharges_10min.csv` — discharges comparison

---

## Key Parameters

These can be adjusted at the top of `Digital_Twin_10_minute.py`:

| Parameter | Default | Description |
|---|---|---|
| `NUM_RUNS` | 100 | Number of simulation replications |
| `FORECAST_HOURS` | 12 | Forecast horizon in hours |
| `ED_PROBABILITY` | 0.675 | Probability a patient enters the ED pathway |
| `STEP_MINUTES` | 10 | Time resolution of the simulation |
